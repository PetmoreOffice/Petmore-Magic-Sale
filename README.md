# Petmore Magic Sale

ระบบงานขายหน้างาน (อีเวนต์) และคลังสินค้าของร้านอาหารสัตว์ ธีม Magic × ร้านอาหารสัตว์ ขึ้นโครงใหม่จากระบบเดิมบน Google Apps Script แผนภาพระบบล่าสุดอยู่ที่ [docs/uml](docs/uml) กติกางานทั้งหมดอยู่ใน [CLAUDE.md](CLAUDE.md)

ใช้ได้ 3 แบบจากเว็บแอปตัวเดียว:

| อุปกรณ์ | วิธีสแกน |
|---|---|
| Handheld (Zebra, Honeywell, Urovo ฯลฯ) | หัวสแกนในตัวเครื่อง ทำงานแบบคีย์บอร์ด ต้องตั้งให้ส่ง **Enter** ต่อท้าย (Zebra: DataWedge → Keystroke output → Send ENTER) |
| คอม + เครื่องสแกน USB | ทำงานแบบคีย์บอร์ดเหมือนกัน |
| โทรศัพท์ | กดปุ่มกล้องข้างช่องสแกน (ต้องเปิดเว็บผ่าน **https://** เท่านั้น) |

## โครงสร้าง

งานขายหน้างาน (ใช้ในงานอีเวนต์):

| หน้า | ใครใช้ | ทำอะไร |
|---|---|---|
| `/orders` ออเดอร์สินค้า | Sup (PICKER) | จดออเดอร์ เลือก/สแกนสินค้า (บาร์ L เรทส่งสลับให้เองเมื่อครบ 12 ชิ้น, ซ่อนสินค้าแคมเปญคละ KK) พิมพ์ใบออเดอร์ |
| `/check` ตรวจของเบิก | แอดมิน (CHECKER) | สแกนใบออเดอร์แล้วสแกนของทีละชิ้น ให้ขนาดอื่นแทนนับเป็นชิ้น ของไม่พอยืนยันได้ รายการรีเฟรชเองทุก 20 วินาที |
| `/returns` คืนสินค้า | แอดมิน | คืนจากออเดอร์หรือใบคืนอิสระ แยกของดี/เสียหาย พิมพ์ใบคืนพร้อมช่องเซ็นชื่อ |
| `/users` จัดการผู้ใช้ | ผู้ดูแลระบบ (ADMIN) | 3 ตำแหน่ง + สิทธิ์รายข้อ 19 ข้อ ประวัติการแก้ไข |

ออเดอร์ ผลตรวจ และใบคืน เก็บใน PostgreSQL ของแอปเท่านั้น ไม่มีการเขียนไป SQL Server บริษัท และยังไม่ตัดหรือเพิ่มสต็อก Sup เห็นเฉพาะออเดอร์ที่ตัวเองจด ผู้มีสิทธิ์ `users.manage`, `picks.check` หรือ `returns.create` เห็นทุกออเดอร์

เพิ่มตารางบนฐานข้อมูล local ด้วย `node scripts/migrate-local-orders.cjs` (ปฏิเสธปลายทางอื่นนอก `localhost:5432/petmore_wms`) ทดสอบหลัง build ด้วย `node scripts/test-orders.cjs`; การทดสอบใช้ transaction แล้ว rollback ข้อมูลทดสอบทั้งหมด

```
packages/shared   สิทธิ์ 19 ข้อ 3 ตำแหน่ง + type และกติกาที่ใช้ร่วมกัน (บาร์ L, สินค้าแคมเปญ)
apps/api          NestJS + Prisma + PostgreSQL
  prisma/schema.prisma   โครงข้อมูลตาม Class Diagram
  src/receiving          รับสินค้า (transaction: ใบรับ + เพิ่มสต็อก + Movement)
  src/moves              ย้าย Location (ตัดยอดแบบกันติดลบเมื่อกดพร้อมกัน)
  src/scan               GET /api/scan/:code → บอกว่าเป็นสินค้าหรือ Location
  src/orders, src/returns  ออเดอร์ ตรวจของเบิก คืนสินค้า
  src/sync               ดึงสินค้า ขนาดบรรจุ และผู้สั่งจาก SQL Server บริษัท (อ่านอย่างเดียว) ทุก 15 นาที
apps/web          React + Vite + PWA (ติดตั้งเป็นไอคอนบนมือถือ/Handheld ได้)
  src/components/ScanInput.tsx   ช่องสแกนเดียวใช้ได้ทุกอุปกรณ์
```

## เริ่มใช้งานครั้งแรก

ต้องมี Node.js 22 ขึ้นไป และ PostgreSQL (ติดตั้งเอง หรือใช้ Docker Desktop)

```bash
npm install
```

```bash
copy apps\api\.env.example apps\api\.env
```

แก้ `apps/api/.env`: ตั้ง `DATABASE_URL` ให้ชี้ PostgreSQL และตั้ง `SEED_ADMIN_USERNAME` / `SEED_ADMIN_PASSWORD` (อย่างน้อย 8 ตัวอักษร) สำหรับผู้ดูแลคนแรก

```bash
npm run db:up
```

(ข้ามขั้นนี้ถ้าติดตั้ง PostgreSQL เองแล้ว)

```bash
npm run db:migrate
```

```bash
npm run db:seed
```

```bash
npm run dev
```

เปิด http://localhost:5173 แล้วเข้าสู่ระบบด้วยบัญชีผู้ดูแลที่ตั้งไว้

## ทดสอบกล้องบนมือถือ

มือถือกับคอมต้องอยู่ Wi-Fi เดียวกัน

```bash
npm run dev:https -w @petmore/web
```

เปิด `https://<IP ของคอม>:5173` บนมือถือ แล้วกดยอมรับใบรับรองทดสอบ ตอนใช้งานจริงให้ใช้โดเมนที่มีใบรับรอง HTTPS จริง

## เชื่อม SQL Server บริษัท

1. ขอ IT สร้าง user บน SQL Server ที่มีสิทธิ์ **SELECT อย่างเดียว** เฉพาะตารางสินค้า
2. ใส่ `MSSQL_HOST`, `MSSQL_DATABASE`, `MSSQL_USER`, `MSSQL_PASSWORD` ใน `apps/api/.env`
3. ตั้ง `MSSQL_PRODUCT_QUERY` (สินค้าหลัก) และ `MSSQL_PACK_QUERY` (ขนาดบรรจุ/บาร์โค้ด) ให้ตรงตารางจริง ชื่อคอลัมน์ผลลัพธ์ดูที่ type `ProductRow`/`PackRow` ใน `apps/api/src/sync/sync.module.ts` คำสั่งที่ใช้จริงอยู่ใน `apps/api/.env` ของเครื่องพัฒนา **สำรองไว้ด้วย** (ไม่อยู่ใน git)
4. ระบบ sync เองทุก 15 นาที หรือสั่งทันทีด้วย `POST /api/sync/products` (ต้องมีสิทธิ์ `products.manage`)

สินค้าที่มาจาก SQL Server (`source = COMPANY`) แก้ใน WMS ได้เฉพาะ "ต้องกรอกวันหมดอายุ" ส่วนชื่อ บาร์โค้ด และหน่วย ให้แก้ที่ระบบบริษัท

## สิ่งที่ทำแล้ว / ยังไม่ทำ

ทำแล้ว:
- เข้าสู่ระบบ (บัตรเข้างาน) / ออก / หมดอายุ 12 ชม. / ตรวจสิทธิ์ใหม่ทุก 60 วินาที / กันเดารหัส + จำกัดคำขอต่อ IP
- ผู้ใช้ 3 ตำแหน่ง + สิทธิ์รายข้อ + จำกัดคลังรายคน + ประวัติการแก้ไข (หน้า `/users`)
- งานขายหน้างาน: ออเดอร์ ตรวจของเบิก คืนสินค้า พร้อมเอกสารพิมพ์
- งานคลัง: รับสินค้า ย้าย Location ดูสต็อก พิมพ์ป้าย Location

มี API แล้ว แต่ยังไม่มีหน้าเว็บ:
- ทะเบียนสินค้า และการนำเข้าจาก Excel
- คลัง / โซน / Location (สร้างและแก้ไข)
- รายการใบรับย้อนหลัง พิมพ์ใบรับ ประวัติ Movement

ยังไม่มีชุดทดสอบอัตโนมัติใน repo (ทดสอบด้วยสคริปต์ชั่วคราวกับฐานข้อมูลในเครื่อง แล้วลบข้อมูลทดสอบทิ้ง)

ยังไม่รองรับ: ทำงานตอนไม่มีเน็ต (offline)
